# Контекст BotArena

BotArena — учебная браузерная платформа для разработки и сравнения алгоритмов управления танками. Гавриил Купцов ведёт платформу, симуляцию и исполнение стратегий. Карты и режимы, визуализация, дизайн механик и UGC — отдельные направления команды. [Страница проекта в CS Unicorns Wiki](https://cs-uni.ru/index.php?title=BotArena).

Первый этап — локальная дуэль 1×1 на карте с укрытиями. Пользователь редактирует JavaScript, выбирает одного из двух встроенных противников, запускает расчёт и просматривает реплей. Командные матчи, захват флага, генерация карт, разные виды оружия, обмен стратегиями и отладчик относятся к дальнейшим этапам. У локального MVP нет аккаунтов и базы данных.

## Поток матча

1. React отправляет код и ID противника. ASP.NET Core валидирует запрос и допускает один расчёт одновременно.
2. Рабочий процесс запускает отдельный экземпляр Jint для каждой стратегии. `Match` получает наблюдения с одного и того же тика и собирает обе команды до вызова `Duel.Step`.
3. `Duel` считает разгон, поворот корпуса и башни, столкновения прямоугольников, снаряды, перезарядку и урон. Стены перекрывают видимость и снаряды. Снаряд проверяется вдоль пройденного отрезка.
4. Начальное состояние имеет тик 0. Матч идёт при 20 тиках/с до уничтожения танка или 200 тиков (10 игровых секунд). Если к концу десятой секунды оба танка живы, матч заканчивается ничьей независимо от HP.
5. Сервер возвращает реплей целиком. React интерполирует координаты и углы соседних кадров, отображает события и позволяет ставить запись на паузу, перематывать и менять скорость.

## Контракт стратегии

Координаты отсчитываются от левого верхнего угла, X вправо, Y вниз. Углы в радианах, положительное направление по часовой стрелке. `state` содержит `tick`, `self`, `enemy`, `bullets` и `arena`. Противник за стеной скрыт (`enemy: null`). Пули видны по всей карте. У бота есть `id`, `position`, `bodyAngle`, `turretAngle`, `speed`, `hp`, `maxHp`, `reloadingTime` (секунды) и `canShoot`. Стены заданы верхним левым углом и размером.

Синхронная `tick(state)` возвращает объект с `leftTrack`, `rightTrack`, `aimDirection: { x, y }` и `shoot`. Поля опциональны. Вектор `{ x: 0, y: 0 }` сохраняет угол башни. Команды гусениц ограничиваются диапазоном от −1 до 1. Неконечные числа и неверные типы вызывают ошибку стратегии. Угловые скорости корпуса и башни ограничены и плавно приближаются к заданным. Выстрел идёт по фактическому углу башни в текущем кадре.

## HTTP

- `GET /api/opponents` возвращает `[{ id, name, description }]`.
- `POST /api/matches` принимает JSON `{ botCode, opponentId }` и возвращает `{ replay, error }`. Реплей содержит `tickRate`, `arena`, `frames`, `result`. `error` равен `null` либо содержит `{ botId, tick, message }`.
- Ошибка загрузки стратегии возвращает HTTP 422 с `{ error: string }`. При ошибке на тике возвращается HTTP 200 с уже рассчитанными кадрами, `result.reason = "BotError"` и ошибкой бота. Тик ошибки остаётся последним кадром, победа присуждается другой стороне.
- Невалидные параметры дают HTTP 400, занятый сервер — 429. Сбой или истечение срока рабочего процесса даёт 422 с сообщением.

## Источники и решения

[Первый черновик MVP](https://docs.google.com/document/d/1hnUugPaCYpZwnkgOa9hRNtzfW_xCLBFmPvQUfq1d-Oo/edit) описывает общий цикл, REST и JS/Jint. Для полей и модели движения приоритет отдан уточняющему контракту v0.1 и его двум комментариям о прямоугольных границах. В нём таблица действий расходится с примерами и общими соглашениями. Принят интерфейс гусениц из примеров и отдельный `bodyAngle` из описания состояний и рендера. Для воспроизведения используется готовый JSON. Движок не использует случайность, а пользовательский JavaScript может использовать время или случайные числа, поэтому повторный расчёт не обещает тот же результат.

Сервер слушает loopback. Jint работает без CLR-доступа и динамической компиляции строк, с лимитами инструкций, глубины вызовов, памяти и времени. Рабочий процесс имеет ограничение управляемой кучи и принудительный дедлайн расчёта 5 секунд реального времени. Для публичного исполнения чужого кода нужны отдельные права процесса и ограничения ресурсов на уровне ОС. [Модель угроз Jint](https://sebastienros.github.io/jint/guide/untrusted-code).
